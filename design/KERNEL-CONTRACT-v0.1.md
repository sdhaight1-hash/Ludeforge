# Kernel contract v0.1 — proposed implementation target

Status: candidate specification for issues #2–4 and #6–8. [Prior research](KERNEL-RESEARCH.md), [source study](../research/2026-11-22-kernel-source-study.md), [fixtures](../examples/REFERENCE-FIXTURES.md). Sections marked deferred are not required for Phase 1.

## Authoring model

Project envelope: format_version=1, project_id, label, types[], objects[], relations[], rules[] (rules empty in Phase 1). IDs are opaque ASCII strings 1–64 characters matching [A-Za-z][A-Za-z0-9_-]*, globally unique within a project across types, objects, relation definitions, relation records, rules and fields/options. Prefixes help readability but do not encode semantics. IDs immutable under rename; reject collisions. Labels Unicode and independent of identity. Fields belong to their type, values keyed by field ID. Unknown fields reject; missing required fields reject; optional omitted fields are absent. Null rejected in v1, explicit unknown deferred. Values tagged bool, int, text, enum(option ID), ref(object ID). Integer domain [-9007199254740991,9007199254740991] inclusive, checked operations; no implicit conversion, floats, NaN or exponent syntax in canonical output. Bounds and enum choices validated. References resolve within project and target declared type. No implicit inheritance, defaults, inferred membership or schema code execution. Definition objects and runtime instances separate; v1 authoring model contains no mutable campaign state.

Relations: relation type has source type, target type, directed or symmetric mode, optional unique pair constraint. Relation record has stable ID and endpoints. For symmetric relation require identical endpoint type and canonical endpoint order; optional self-edge prohibition. No universal acyclicity. Relation cardinality and field-to-field constraints can be explicit later pure expressions; in Phase 1 record fixture expectations and reject unsupported executable constraints rather than pretending to validate them.

## Persistence

Recommend single UTF-8 versioned JSON file authoritative in Phase 1. Reject duplicate JSON keys before deserialization, malformed input, unknown top-level fields or versions. Use ordered arrays where author order has semantics, otherwise sort collections by ID when producing normalized output. Stable bytes for LF-specific canonical form only; not RFC 8785 unless tested. Reading must validate entire candidate before replacing current open project. Initial MVP CLI read/validate/normalize only; writes to new path first, no destructive in-place save until tested same-directory replacement, failure recovery and concurrent modification handling. Project format version distinct from semantic revision and runtime version. SHA-256 of explicitly versioned canonical semantic bytes candidate for revision binding; exclude view layout only through defined projection; do not exclude content used in execution. SQLite deferred pending actual workloads; derived index never a competing writer. No automatic cross-repo imports.

## Typed IR (Phase 2)

Expressions (pure): literal, argument, local binding, property read using field ID, ref equality, boolean and/or/not (short circuit), integer add/sub/mul with checked bounds, comparisons, explicit integer division/rounding only once semantics specified. Conditional expression typed both branches. No I/O, clock, RNG, evaluation of user code, mutation, recursion. Limits: candidate 64 nesting depth, 4096 expression nodes, 10000 interpreted steps per action; parse and validate before execution; budget failure leaves mechanical state unchanged. Limits provisional until measurements. Explicit errors for missing read, overflow, division by zero, incompatible types and budget.

Rules: typed parameters; guard expressions; ordered statement list: bind, require, set field, branch, emit, request uniform integer, request human choice. First prototype may support only integer field writes on declared runtime instances, not arbitrary creation/deletion. Reads see tentative sequential state; other actions see committed state only. Emit creates tentative event, not recursive dispatch. No loops, implicit triggers or simultaneous updates initially. Compile checks all branches, IDs, field types, authority and input schemas; collect possible read/write sets including guard references. Derived expressions are acyclic and pure. Future bounded collection iteration, relation changes, aggregate and modifier operators, schedules, creation, and temporal feedback require fixture evidence. Collect runtime read/write/choice traces for actual outcomes. Distinguish potential conflicts from observed conflicts.

## Runtime protocol

Request(id, rule_version, expected_revision, typed_args, authorized_actor). Identity scoped to run; repeated exact request returns stored outcome or pending receipt; conflicting payload rejected. Compile/validate before invoking external inputs. Stage mechanical effects/events, record explicit draw results with stable instruction ID and occurrence; suspend if missing choice. Pending checkpoint includes request identity, rule version, initial revision, program position, typed locals and tentative effects (or enough deterministic input to recompute), required input kind and allowed authority. On resume require current revision and matching checkpoint identity; invalid or unauthorized choice does not consume checkpoint, stale checkpoint marked unusable. Cancellation records administrative receipt, not mechanical success. Terminal rejection commits no mechanical changes; legitimate failed attempt may incur expressly defined effects. Commit state, revision, receipt and events atomically; duplicate resume returns prior outcome without effects. Use bounded in-memory runtime before durable journal; do not claim crash recovery until implemented. No live provider in replay. Compare event application and deterministic re-execution separately.

## Diagnostics and security

Stable diagnostic codes with severity, referenced object/field/rule, JSON path and message. Sort by source path/code/ID to make output repeatable. No silent correction of invalid projects. File size, collection size, nesting and expression limits before allocation or traversal; provisional 16 MiB project input bound, 100k total records, 64 levels. Reject untrusted scripts, paths, external imports and network reads at MVP boundary.

## Acceptance mapping

Phase 1: Lantern and Council valid semantic model (rules not yet executed), negative type/reference/ID/version cases, round-trip deterministic bytes. Phase 2: implement original Lantern success/failed-attempt/invalid cases and Council checkpoint; retain transaction invariants, compare event replay; model tests cover duplicates, stale and unauthorized requests. Glass Market, Tidemill, Wayfarer and Mosswater expose future operation requirements without prematurely hardcoding those domains.

Outstanding: fixture data authoring and versioned schema, exact optional-value and constraint syntax, runtime snapshot persistence, cancellation receipts, multi-action scheduling, numeric units, explicit migration policy, formal diagnostic registry. This contract is a proposed baseline, not production behavior or a closed issue.
