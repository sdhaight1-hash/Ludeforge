Method: reviewed primary project documentation, public repository descriptions and publisher abstracts; no installations, benchmarks or full external code audit. Features reported by projects are not experimentally verified. Source licenses are screening observations, not legal approvals. Do not copy any source before verifying the exact license at the intended revision, dependencies, and compatibility with the owner's chosen license.

## Design alternatives

A: universal scripting host (very expressive but difficult to analyze, bound and make accessible). B: fixed RPG schema (fast for one family, fails diceless/custom concepts). C: constrained typed entity model plus executable rule IR and explicit human decision boundary (recommended first prototype). D: unrestricted ontology and logical inference engine (high expressivity but costly semantics, ambiguity, reasoning and migration overhead). Extend C only when concrete fixtures expose missing primitives; allow a later explicitly sandboxed extension boundary that declares analytical limits.

## Research gaps

- Need source-level review of QBScript execution and storage, Cruncher expression/stacking rules, Mechflow loop/step semantics, Icepool algorithm paper, and actual license files.
- Need independent measurements of author task success, not claims about all existing TTRPG applications.
- Investigate general game descriptions beyond Ludii, typed DSL/IR, total expression languages (e.g. CEL), constraint solvers, statecharts and temporal logic, resource-flow models, visual programming usability, data-driven narrative and open-world adjudication.
- Test competing persistence representations and data structures under representative edits; theoretical claims do not settle workload-specific costs.
- Define balance goals as designer objectives with explicitly modeled policies; avoid universal fairness score or unsupported market novelty claims.
